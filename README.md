# classify-sessions

Classifies Claude Code session logs by purpose (debug, implement, refactor, test, review,
research, plan, ops) and reports what each purpose costs at public prices, with an honest
account of what could not be parsed or priced. Extra: a model-choice analysis that asks whether
the most expensive model buys anything. Built and tested on the official synthetic dataset only.

## Run it

Three ways, from least to most installed. Each serves the same JSON; the page needs Node or
Docker.

**1. Go only** (Go 1.27.2; with `GOTOOLCHAIN=auto`, the default, Go downloads it from
`backend/go.mod`):

```bash
cd backend
go test ./... -count=1
go run ./cmd/sessions summary --input ../fixtures/claude-code --labels ../fixtures/labels/heldout.json
go run ./cmd/sessions serve --input ../fixtures/claude-code --labels ../fixtures/labels/heldout.json
curl -s http://127.0.0.1:8080/api/summary
curl -s http://127.0.0.1:8080/api/models
```

If port 8080 is taken, add `--listen 127.0.0.1:8081` to `serve`.

**2. Go + Node 22** (the page, served by Vite):

```bash
cd frontend
npm ci
npm run dev        # http://127.0.0.1:5173, proxies /api to 127.0.0.1:8080 (run `serve` first)
npm run dev:mock   # the page from contract/examples, no backend needed
```

If `serve` runs on another port: `API_PROXY_TARGET=http://127.0.0.1:8081 npm run dev`
(loopback targets only; anything else stops the dev server).

**3. Docker** (page and API together):

```bash
docker compose up --build -d   # http://127.0.0.1:8088
docker compose down
```

Checks: `node .claude/skills/privacy-scan/scan.mjs` (privacy scan);
`cd fixtures && sha256sum -c claude-code.sha256` (fixture manifest).

## What works

On the 34-session synthetic corpus (numbers from `evidence/`, regenerated by `/corpus-check`):

- **Coverage.** Every nonblank line is counted once: 1107 = 1084 parsed + 1 malformed + 0
  unknown + 22 duplicate. Unit-tested.
- **Purpose.** All 34 sessions get a category from rules-v1 (debug 4, implement 6, refactor 3,
  test 5, review 6, research 4, plan 3, ops 3); on the ten held-out sessions the rules agree with
  the labels 10 of 10 (see "What does not" for how to read that). Unit-tested.
- **Cost.** Known spend USD 38.01359025 at dated public rates, reported as a lower bound because
  17 sessions are incomplete (missing usage, no cache fields or `[1m]` requests). It reconciles
  exactly with the synthetic OpenTelemetry export once four named pricing differences are
  accounted for. Unit-tested.
- **Model choice.** `GET /api/models` and the fifth panel: Opus 4.1 sessions cost 5.1x
  Sonnet 4.5 sessions on average, and the logs are too thin to say whether that buys fewer
  corrections (verdict `insufficient_evidence`). Unit-tested.
- **Boundary.** The API answers only loopback requests for its own origin (GET and HEAD, JSON
  errors, no-store and a strict CSP); nothing loads from or calls outside the machine.
  Live-HTTP-checked on the dev setup and docker-checked on 127.0.0.1:8088.
- **Page.** Five sections (what the sessions cost, what they were for, where the money goes,
  what could not be counted, whether the expensive model is worth it), every value from the API,
  text only, no external asset or font. Per-session rows are in the API (`session_list`), not on
  the page. Browser-checked against the live API at desktop and phone widths, and
  docker-checked on 127.0.0.1:8088.

## What does not

- **Only synthetic data.** No real session log was ever read; real logs may contain record
  shapes, content blocks or wording the parser and rules have not seen.
- **The classifier is keyword rules.** It never returns `unknown` on this corpus because the
  prompts are templated; real prompts would often fall to `unknown` or to the first keyword they
  contain. The 10 of 10 held-out agreement compares rules a Claude model wrote with labels a
  Claude model proposed, on ten sessions: a consistency check, not an accuracy.
- **Prices are as recorded on 2026-10-09** and were not re-checked against the live pricing page
  from this repository. `[1m]` requests are priced at base rates; whether any exceeds the
  long-context threshold is not tested.
- **The model-choice analysis is descriptive.** Correction messages are found by keyword rules,
  and no category has three sessions per model, so it can name the cost premium but not judge it.
- **Untested here:** the fallback if the Go 1.27.2 download fails, a reviewer machine without
  Docker Desktop, and `npm audit` reports 3 findings in the test runner (`vitest`), which is not
  part of the built page.
