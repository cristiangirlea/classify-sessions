# CLAUDE.md

This repository classifies synthetic Claude Code session logs by purpose and reports what each
purpose costs, through a Go JSON API and a React page. This file steers the agent working in
the repository; SPEC.md is for the human reviewer, AGENTS.md for parallel workers.

@AGENTS.md

Provenance: written before any contract or product code existed. An earlier attempt at the
same brief exists outside this repository; NOTES.md discloses what carried over (data facts
only, no code).

## Directory map

| Path | What |
| --- | --- |
| `backend/` | Go 1.27.2, standard library only. `cmd/sessions` CLI, `internal/*` packages |
| `frontend/` | Vite 7 + React 19 + TypeScript 5. `src/api/contract.gen.ts` is generated |
| `contract/` | JSON Schemas and examples: the only boundary between backend and frontend. Frozen |
| `fixtures/` | official synthetic dataset (read-only), OTel oracle, held-out labels (`labels/heldout.json`, frozen), hand-made edge cases (`synthetic/`) |
| `evidence/` | outputs regenerated by `/corpus-check`; every number in a document comes from here |
| `.claude/` | settings, Bash guard hook, `go-worker` and `react-worker` agents, three skills |
| `.cursor/rules/` | written for parity; Cursor was not used |

## Commands

```bash
# backend (from backend/)
go vet ./... && go test ./... -count=1
go run ./cmd/sessions summary --input ../fixtures/claude-code --labels ../fixtures/labels/heldout.json
go run ./cmd/sessions serve --input ../fixtures/claude-code --labels ../fixtures/labels/heldout.json   # 127.0.0.1:8080; --listen to change
go run ./cmd/sessions evaluate --input ../fixtures/claude-code --labels ../fixtures/labels/heldout.json
go run ./cmd/sessions prompts --input ../fixtures/claude-code --exclude-labels ../fixtures/labels/heldout.json
go run ./cmd/sessions crosscheck --input ../fixtures/claude-code --otel ../fixtures/otel/claude-code-events.jsonl

# frontend (from frontend/)
npm ci && npm run contract:check && npm run typecheck && npm test && npm run build
npm run dev:mock      # serves contract/examples at /api/*, no backend needed
npm run dev           # proxies /api to 127.0.0.1:8080; API_PROXY_TARGET=http://127.0.0.1:<port> overrides (loopback only)

# docker (from the root)
docker compose build && docker compose up -d     # page and API on 127.0.0.1:8088

# skills
/corpus-check   /review-step   /privacy-scan
node .claude/skills/privacy-scan/scan.mjs        # the script the privacy-scan skill runs
```

## Hard barriers

- Synthetic fixtures only. Never read real session logs, `~/.claude`, `~/.codex`, Cursor data, or
  anything outside this repository. The Bash hook and the deny rules enforce part of this.
- Nothing leaves the machine at runtime: loopback only, no external URL in code except the
  pricing source string.
- No prompt text, absolute paths or usernames in JSON output, the page, tests' golden files,
  docs or commit messages. Session ids and rule ids only.
- Every nonblank record is counted exactly once as parsed, malformed, unknown or duplicate.
- Unknown cost is never zero: it is reported as incomplete and the known part as a lower bound.
- The first genuine prompt is chosen in timestamp order, not file order.
- `fixtures/labels/heldout.json` is frozen and never read while writing or tuning rules. Tune on
  the 24 other sessions via `prompts --exclude-labels`.
- `contract/` is frozen. A change is a coordinator-only commit approved by the owner.
- `fixtures/claude-code/`, `fixtures/otel/` and `fixtures/claude-code.sha256` are never edited.
- No commit, push or PR unless the owner asked for that step. No `Co-Authored-By` trailer or
  generated-by footer (`attribution` is empty in settings); AI authorship is documented in
  NOTES.md and PROMPTS.md.
- Every test and check runs locally in the working copy; there is no CI and no GitHub workflow.
- The repository records no times, in documents, commit messages or PR descriptions. PLAN.md
  holds the PR sequence, PR contents and cut order.
- SPEC.md has exactly five sections (problem, format findings, decisions on unsettled points,
  out of scope, how customer and employer data were kept out). Findings and decisions are
  appended as tests confirm them; existing SPEC text is not rewritten.
- Generated files (`frontend/package-lock.json`, `frontend/src/api/contract.gen.ts`) are marked
  `linguist-generated` in `.gitattributes`; every PR description states how many of its lines
  are generated.

## Honesty rules

Every claim in a document carries one evidence level: unit-tested, live-HTTP-checked,
browser-checked, docker-checked, owner-confirmed, or unverified. Numbers come from
`evidence/` via `/corpus-check`; a number without a command behind it is labelled unverified.
When a worker's claim is disproved, it goes in the NOTES.md "AI was wrong" table.

## Definition of done per PR

1. `go vet ./... && go test ./... -count=1` and the frontend chain above are green.
2. `/corpus-check` run after any parser, rule or price change; its block pasted into NOTES.md.
3. `/review-step` shows no blocking finding; `/privacy-scan` exits 0.
4. PROMPTS.md has the PR's section with every prompt verbatim.

## Environment notes (Windows host)

- Multi-line heredocs in the Bash tool have failed on this machine before; put one-off scripts in files.
- Windows PowerShell 5.1 lacks `[IO.Path]::GetRelativePath`.
- `GOWORK=off` is unnecessary here (no parent go.work), but needed under a parent workspace.
- `GOTOOLCHAIN=auto` downloads Go 1.27.2 from `go.mod` on first use.
